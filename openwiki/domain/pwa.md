# Progressive Web App

OpenEdu is a Progressive Web App that supports offline-first learning, installability, automatic updates, and low-bandwidth operation. The PWA layer enables learners to download courses, disconnect from the internet, and continue learning with full progress persistence.

## Packages

| Package             | Purpose                                                                         |
| ------------------- | ------------------------------------------------------------------------------- |
| `packages/pwa-core` | Framework-agnostic PWA primitives (install, update, connectivity, storage info) |
| `packages/storage`  | IndexedDB persistence with 6 typed object stores                                |

## Architecture

The PWA layer sits between the learner app and the browser platform:

1. `vite-plugin-pwa` + Workbox generates the service worker at build time
2. `@open-edu/pwa-core` provides platform-level APIs (install, update, connectivity, storage)
3. `@open-edu/storage` provides IndexedDB persistence via the `idb` library
4. React hooks in the learner app bridge these to UI components

## Service Worker

Generated by `vite-plugin-pwa` using Workbox. Configuration lives in `apps/learner/vite.config.ts`.

### Caching strategies

| Resource                       | Strategy             | Purpose                                            |
| ------------------------------ | -------------------- | -------------------------------------------------- |
| Static assets (JS, CSS, fonts) | CacheFirst           | Fastest load from cache                            |
| API / metadata endpoints       | NetworkFirst         | Fresh data when online, cache fallback offline     |
| Course catalog listings        | StaleWhileRevalidate | Show cached data immediately, update in background |

### Important constraints

- The service worker does NOT store course content — that goes in IndexedDB
- The dev server does not generate a real service worker — use `pnpm build && pnpm preview` for testing
- Updates are never forced — the user chooses when to apply

## IndexedDB Storage

`@open-edu/storage` provides 6 typed object stores in the `open-edu` database (version 2):

| Store            | Key                    | Data                                                 |
| ---------------- | ---------------------- | ---------------------------------------------------- |
| `courses`        | `id`                   | Downloaded course packages (manifest, nodes, assets) |
| `progress`       | `[courseId, lessonId]` | Per-node learning progress                           |
| `search-indexes` | `locale`               | Persisted MiniSearch indexes                         |
| `preferences`    | `locale`               | User preferences (locale, theme, font size)          |
| `badges`         | `courseId`             | Earned badge records                                 |
| `cards`          | `cardId`               | Knowledge Card level and unlock timestamp            |

All learner persistence was migrated from localStorage to IndexedDB. Bundle progress uses a `__bundle__` sentinel in the `data` field; snapshot progress uses a `__snapshot__` sentinel.

## PWA Core API

`@open-edu/pwa-core` exports framework-agnostic functions:

### Install

- `getInstallState()` — returns `{ isInstallable, isInstalled, platform }`
- `promptInstall()` — triggers browser install prompt, returns `{ outcome }`

### Update

- `registerUpdateListener(callback)` — monitors service worker updates, returns unsubscribe function
- `getUpdateState()` — returns `{ updateAvailable, registration }`
- `skipWaiting()` — activates waiting service worker immediately

### Connectivity

- `getOnlineStatus()` — returns `navigator.onLine`
- `onOnlineStatusChange(callback)` — listens for online/offline events

### Storage

- `getStorageUsage()` — returns `{ usage, quota, percentage }` via Storage Manager API

## Learner App Integration

React hooks bridge `@open-edu/pwa-core` to the UI:

| Hook               | Component                                  | Location              |
| ------------------ | ------------------------------------------ | --------------------- |
| `useInstallPrompt` | `InstallPrompt`                            | Catalog page          |
| `useUpdatePrompt`  | `UpdatePrompt`                             | App shell             |
| `useOnlineStatus`  | `OfflineBanner`                            | App shell             |
| `useStorageUsage`  | `StorageUsageCard`, `DownloadedCourseList` | Storage settings page |

## Key files

- `apps/learner/vite.config.ts` — VitePWA plugin config, runtime caching rules
- `apps/learner/src/AppShell.tsx` — mounts UpdatePrompt and OfflineBanner
- `apps/learner/src/CatalogPage.tsx` — mounts InstallPrompt
- `apps/learner/src/pages/StorageSettingsPage.tsx` — storage management UI
- `apps/learner/src/hooks/useInstallPrompt.ts` — install detection hook
- `apps/learner/src/hooks/useUpdatePrompt.ts` — update detection hook
- `packages/pwa-core/src/index.ts` — PWA primitives entry point
- `packages/storage/src/index.ts` — storage API entry point
- `packages/storage/src/db.ts` — IndexedDB schema and version migration

## Testing

- Build verification: `pnpm --filter @open-edu/learner test -- --run src/__tests__/build-output.test.ts`
- A11y tests: `pnpm --filter @open-edu/learner test -- --run src/__tests__/*a11y*.test.tsx`
- Full PWA testing requires production build: `pnpm build && pnpm --filter @open-edu/learner preview`

## Where to look when changing PWA behavior

- Service worker caching rules: `apps/learner/vite.config.ts`
- Install/update/connectivity primitives: `packages/pwa-core/src/`
- IndexedDB schema and stores: `packages/storage/src/db.ts`
- React hooks and UI components: `apps/learner/src/hooks/` and `apps/learner/src/components/`
- Storage migration logic: `apps/learner/src/progressStorage.ts`, `apps/learner/src/bundleProgressStorage.ts`, `apps/learner/src/badgesStorage.ts`, `apps/learner/src/cardsStorage.ts`
