# Studio Creator Mode — Outline & Editor Improvements

**Date:** 2026-08-08
**Scope:** `apps/dev-server` Creator mode (outline page, activity editors, widget preview/catalog)
**Stories:** 6 independent work items, each ship-ready with Vitest coverage (per AGENTS.md rule 1).

---

## 1. Summary

Six UX gaps reported by users in the Creator-mode outline/editor experience:

1. **Reset preview does not reset widget state** — the button is a dead control.
2. **No cancel/back option in the edit page** — editors only offer Save.
3. **No delete option for items in the outline page.**
4. **Widget guide markdown is not shown in the widget editor** even though `apps/docs/docs/widget-library/*.md` pages exist.
5. **"Add practice" only shows 3 widgets** although the catalog ships ~27 usable ones.
6. **No JSON value validation in the edit forms** — malformed JSON in config fields is silently ignored.

All six are implemented in `apps/dev-server` (plus a small shared change in `packages/widgets` and one i18n key file). No schema changes are required.

Key mechanics that shape the design:

- **Outline order source of truth is `workflow.json` routing.** `GET /api/package/outline` derives `orderedPaths = Object.keys(workflow.routing)` (`vite.config.ts:1155-1162`). Deleting a node file without updating routing leaves the item visible. Therefore delete = delete file + `saveOutlineOrder(remaining)`.
- **Empty outline is currently rejected.** `PUT /api/package/outline` returns 400 for an empty `orderedPaths` (`vite.config.ts:1182-1186`), so deleting the last item would fail. `WorkflowSchema` accepts `{ routing: {} }` (`packages/schemas/src/workflow.test.ts:56-57`); `PackageManifestSchema.entry` requires a non-empty string (`packages/schemas/src/manifest.ts:16`), so an empty course must keep a manifest `entry` (stale ref is acceptable for an empty course until the next add fixes it).
- **Widget docs are generated, not hand-maintained.** `generate-widget-docs.ts` renders markdown from the structured `guide` in `packages/widgets/src/widget-catalog-source.ts` (`WidgetGuideData`, lines 8-18). The Studio should reuse the same renderer so docs and editor never drift.
- **Widget registry ships 28 builtins** (`packages/widgets/src/builtins/index.ts`); only `open-edu.multiple-choice-practice` is deprecated (`widget-catalog-source.ts:348-349`, replacement `core.multiple-choice`). `SchemaForm` can render any `Record<string, unknown>` config by value type, and each widget exposes a Zod `schema` for validation (`packages/widgets/src/builtins/MultipleChoice/MultipleChoice.tsx:487`).

## 3. Implementation plan

### Work Item 1 — Cancel / Back in the activity editors

**Goal:** From any activity editor, the user can return to the outline, discarding unsaved form edits.

**Changes:**

- `apps/dev-server/src/studio/components/ActivityEditorRouter.tsx`
  - Add optional `onCancel?: () => void` prop; pass through to `LessonActivityEditor`, `QuizActivityEditor`, `PracticeActivityEditor`.
- Each editor (`LessonActivityEditor.tsx`, `QuizActivityEditor.tsx`, `PracticeActivityEditor.tsx`)
  - Accept `onCancel?: () => void`.
  - Render a secondary "Cancel"/"Back to outline" button next to Save (use `nav.backToOutline` label; icon `ArrowLeft`).
  - When `onCancel` exists, clicking navigates back. No dirty-state tracking in this pass (forms are non-persistent until Save); a dirty-confirm dialog is a follow-up (see Risks).
- `apps/dev-server/src/studio/StudioApp.tsx`
  - Pass `onCancel={() => handleNavigate('outline')}` when rendering `ActivityEditorRouter` (case `'edit-activity'`, lines 135-144).

**i18n** (`packages/i18n/locales/en/studio.json`): add `"editor.cancel": "Cancel"`; `nav.backToOutline` already exists and can be reused for the long label.

**Tests** (`LessonActivityEditor.test.tsx`, `QuizActivityEditor.test.tsx`, `PracticeActivityEditor.test.tsx`, `ActivityEditorRouter.test.tsx`):

- Renders a cancel/back button.
- Clicking it invokes `onCancel`.
- Router passes `onCancel` through to the right editor.

### Work Item 2 — Reset preview actually resets widget state

**Goal:** The "Reset preview" button remounts the preview so widget internal state (answered options, revealed answers, animation steps, interaction log) starts fresh.

**Changes:**

- `apps/dev-server/src/editor/WidgetPreviewPanel.tsx`
  - Add `const [resetToken, setResetToken] = useState(0)`.
  - Wire the existing reset `<Button>` (lines 130-139): `onClick={() => setResetToken((t) => t + 1)}`.
  - In the preview body, give the `WidgetPreviewProvider` + `WidgetPreviewRenderer` subtree a `key={resetToken}` (lines 185-187). Remounting the provider clears `interactions`; remounting the renderer resets the widget component's internal `useState` and the `OasAnimationWrapper`/`animationControllerRef` (the ref lives inside `WidgetPreviewRenderer`, `WidgetPreviewPanel.tsx:27`).
- Optional hardening: in `WidgetPreviewProvider`, add a `reset()` that also clears `interactions` (in case remount is not desired later).

**Note:** The same component is used in Developer-mode `EditorShell.tsx:793`, so this fix covers both modes with one change.

**Tests** (`apps/dev-server/src/editor/__tests__/widget-preview.test.tsx`):

- Clicking "Reset preview" increments a remount key (assert via a spy on widget render count inside `WidgetPreviewProvider`).
- Interaction list is cleared after reset.
- Button renders and is disabled when `widgetType` is null (existing guard, keep).

### Work Item 3 — Delete item in outline page

**Goal:** Each outline row gets a Delete action with confirmation; deleting updates both the file and the `workflow.json` routing.

**Changes:**

- `apps/dev-server/src/studio/studioApi.ts`
  - Add `deleteFile: (path: string) => apiRequest<{ success: boolean; path: string }>('/file', { method: 'DELETE', body: JSON.stringify({ path }) })` — note the existing DELETE endpoint reads `path` from the query string, so either switch it to read the body or send `?path=...` (recommend aligning the client call with the existing query-param endpoint: `fetch \`/file?path=${encodeURIComponent(path)}\`, method DELETE`).
- `apps/dev-server/vite.config.ts`
  - Relax `PUT /api/package/outline` (lines 1180-1240): allow `orderedPaths.length === 0`. When empty, write `{ routing: {} }` and leave `manifest.entry` unchanged (it must stay non-empty per schema). When non-empty, keep current behavior.
- `apps/dev-server/src/studio/components/OutlineView.tsx`
  - Add a `deleteTarget: ActivitySummary | null` state.
  - Render a `Trash2` ghost button per row (alongside move/edit).
  - Open a confirmation `Dialog` (mirror the `LibraryView` archive pattern, `LibraryView.tsx:89-110` and `Dialog` primitives) before deleting.
  - On confirm: `await api.deleteFile(path)`; then `await api.saveOutlineOrder(activities.filter(...).map(a => a.path))`; update local state.
  - Disable the delete button while `saving`/`deleting`.
  - Handle the case where deleting leaves a stale selected path in `StudioApp` (`selectedPath` refers to a deleted node) — reset `selectedPath` on outline navigation (see StudioApp change).

**i18n:** add `outline.delete`, `outline.deleteConfirmTitle`, `outline.deleteConfirmLede` (with `{{title}}` interpolation), `outline.deleteConfirm`, `outline.deleteCancel`.

**Tests** (`OutlineView.test.tsx`):

- Delete button opens the confirm dialog.
- Confirming calls `api.deleteFile(path)` then `api.saveOutlineOrder(remaining)` and removes the row.
- Cancelling does nothing.
- Deleting the last item succeeds (mock server allowing empty `orderedPaths`; assert `saveOutlineOrder` called with `[]`).
- Deleting the entry/first item persists correctly (entry re-derived server-side by `buildLinearWorkflow`).

### Work Item 4 — Show widget guide markdown in the widget editor

**Goal:** While editing a practice activity, show that widget's guide (the same content as `apps/docs/docs/widget-library/*.md`) inline.

**Design decision (recommended):** Make `packages/widgets` the single source of truth by extracting the markdown renderer from `generate-widget-docs.ts` and reusing it in the Studio. This guarantees the editor content and the docs site are byte-identical and avoids reading the docs directory from the dev-server at runtime.

**Changes:**

- `packages/widgets/src/guide-markdown.ts` (new)
  - Export `renderWidgetGuideMarkdown(entry: WidgetCatalogEntry): string` — move the body of `renderPage` from `packages/widgets/scripts/generate-widget-docs.ts:50-108` here (deps: `WidgetGuideData`, `WidgetCatalogEntry`). Export from `packages/widgets/src/index.ts`.
- `packages/widgets/scripts/generate-widget-docs.ts`
  - Import and call `renderWidgetGuideMarkdown` instead of the local `renderPage` (output unchanged).
- `apps/dev-server/src/studio/widgets/curatedCatalog.ts`
  - Extend `CuratedWidget` with `guideMarkdown?: string`; populate it from `renderWidgetGuideMarkdown({ id, name, domain, status, guide })` when a guide exists.
- `apps/dev-server/src/studio/components/WidgetGuidePanel.tsx` (new)
  - Renders `guideMarkdown` via `MarkdownRenderer` from `@open-edu/runtime` (`packages/runtime/src/index.ts:22`) inside a collapsible `<details>` (or a right-hand "Guide" card on wide screens) with a heading like "How this practice works".
- `apps/dev-server/src/studio/components/PracticeActivityEditor.tsx`
  - Render `WidgetGuidePanel` when `curated?.guideMarkdown` is available.

**Alternative considered:** serve the generated md files via a new `/api/studio/widget-guide` endpoint that reads `apps/docs/docs/widget-library/{domain}/{slug}.md`. Rejected as primary: path resolution from the dev-server CWD is fragile and the files are generated anyway. A **structured** guide panel built from `guide` fields (no markdown) is a fallback if bundling markdown is ever a concern.

**Tests:**

- `packages/widgets` unit test for `renderWidgetGuideMarkdown` (contains one-liner, `## Configuration fields` table, example JSON fence).
- `curatedCatalog.test.ts`: `guideMarkdown` is present for a widget with a guide.
- `PracticeActivityEditor.test.tsx`: guide panel appears for `core.multiple-choice` and renders a known string (e.g., the widget name); absent for a widget without a guide.

### Work Item 5 — Expand "Add practice" widget picker

**Goal:** The picker lists all non-deprecated catalog widgets that have a guide (so `SchemaForm` can build a form), instead of the 3-widget allowlist.

**Changes:**

- `apps/dev-server/src/studio/widgets/curatedCatalog.ts`
  - Replace the hardcoded `CURATED_WIDGET_IDS` allowlist with a derivation from the registry: keep `getCuratedWidget(id)` (filters deprecated), and change `listCuratedWidgets()` to return all `getRegistryMap()` entries that are **non-deprecated AND have a `guide`**. Keep `CURATED_WIDGET_IDS` exported (for backward-compat tests) or remove and update the test accordingly.
  - This exposes ~27 widgets (all of `packages/widgets/src/builtins/*`), excluding the deprecated `open-edu.multiple-choice-practice`.
- `apps/dev-server/src/studio/components/WidgetPicker.tsx`
  - No functional change required (search + domain badge already scale), but group by `domain` for readability when >10 items (optional polish).
- Verify `seedConfigFor`/`SchemaForm` handle the newly exposed widgets: they already render any config by value type; `guide.configFields` top-level keys drive seeding (`PracticeActivityEditor.tsx:40-50`).

**i18n:** no new keys required.

**Tests** (`curatedCatalog.test.ts`):

- `listCuratedWidgets()` length ≥ 20 and every item is non-deprecated with a guide.
- Deprecated widget (`open-edu.multiple-choice-practice`) excluded.
- `getCuratedWidget` still returns `core.multiple-choice` and `undefined` for unknown ids.
- Update `OutlineView.test.tsx`/`PracticeActivityEditor.test.tsx` mocks if they assert a fixed picker count (they mock `curatedCatalog`, so likely no change).

### Work Item 6 — JSON value validation in edit forms

**Goal:** Invalid JSON in any config field is surfaced inline, never silently swallowed; widget schema errors appear at field level; Save is disabled with a visible reason.

**Changes:**

- `apps/dev-server/src/editor/SchemaForm.tsx` — `JsonTextarea` (lines 187-212)
  - Add local `error: string | null` state.
  - Validate on change and on blur: valid → `onChange(parsed)`, clear error; invalid → keep the raw text, set an inline error (`Invalid JSON`) and a red border (`border-error` + `aria-invalid`), and **do not** commit.
  - Show `role="alert"` error text below the textarea (reuse `FieldWrapper` styling conventions).
- `apps/dev-server/src/studio/components/PracticeActivityEditor.tsx`
  - Build `fieldErrors: Record<string, ValidationError[]>` by grouping `validationErrors` under `topLevelKey(path)` (the helper already exists at line 29-31) and pass to `<SchemaForm fieldErrors={fieldErrors} ... />`. `SchemaForm`'s `FieldWrapper` already renders the first error per field with `aria-invalid`/`aria-describedby` (lines 214-252).
  - When `nodeJsonValid` is false, keep the existing coaching banner but add a visible reason next to Save (e.g., "Fix the highlighted settings to save") instead of a silently disabled button.
- `apps/dev-server/src/editor/__tests__`/`PracticeActivityEditor.test.tsx`
  - Cover: invalid JSON in a nested field shows an inline error and is not committed; fixing it clears the error; a widget-schema field error renders at the field and blocks save.

**i18n:** add `editor.jsonInvalid` ("Invalid JSON") and reuse `widget.validationFix` where appropriate.

**Note:** Quiz/Lesson editors serialize valid JSON from form state, so they need no JSON-error handling; empty-question validation for the quiz is out of scope (optional follow-up).

## 4. Sequencing

Phases are independent; recommended order (smallest → largest risk):

1. **Phase A** — Work Items 1 (Cancel/Back) and 2 (Reset preview): small, self-contained, immediately testable.
2. **Phase B** — Work Item 3 (Delete) and 5 (Expanded picker): both touch outline/catalog primitives.
3. **Phase C** — Work Item 6 (JSON validation) then 4 (Widget guide): the guide panel depends on the shared `packages/widgets` renderer.

Each phase lands as its own conventional commit (`fix(dev-server): …`, `feat(dev-server): …`) with its tests.

## 5. Risks & decisions

- **Empty-outline semantics (WI 3):** allowing `orderedPaths: []` leaves a stale manifest `entry`. Accepted: the teacher has no activities yet; the next "add" rewrites a valid entry. Verify `readyCheck` (`apps/dev-server/src/studio/readyCheck.ts`) doesn't crash on zero activities (it has an "at least one activity" check).
- **Reset semantics (WI 2):** "Reset preview" resets runtime/interaction state, **not** the config form fields. Keep the form untouched; document via button `title`.
- **Picker scale (WI 5):** ~27 widgets in the picker dialog is fine (max-height + scroll already present). Grouping by domain is optional polish.
- **Guide source of truth (WI 4):** moving `renderPage` out of the docs script is a no-op for docs output; confirm generated md files don't drift after the refactor by re-running `pnpm --filter @open-edu/widgets generate:widget-docs` and checking `git diff` is empty (or only whitespace).
- **MarkdownRenderer deps:** `MarkdownRenderer` uses `useTranslation` + `useRuntimeOptional`; the Studio app is already inside `I18nProvider` (`apps/dev-server/src/main.tsx:38`) and `useRuntimeOptional` is safe without a runtime provider, so no additional providers are needed.
- **Backend tests:** `vite.config.ts` route changes (empty outline, delete body/query alignment) are only covered by E2E/Playwright or manual verification; add a Playwright assertion if a Studio E2E spec exists (`tests/e2e/`).
