# Internationalization

The **i18n** package (`@open-edu/i18n`) provides the internationalization infrastructure for the Open-Edu framework. It handles locale detection, translation loading, string interpolation, React context integration, and formatting utilities.

## Quick Start

```tsx
import { I18nProvider, useTranslation, LanguageSwitcher } from '@open-edu/i18n';
import runtimeDict from '@open-edu/i18n/locales/en/runtime.json';
import learnerDict from '@open-edu/i18n/locales/en/learner.json';

function App() {
  return (
    <I18nProvider
      locale="en"
      supportedLocales={['en', 'hi', 'or']}
      dictionaries={{ en: { runtime: runtimeDict, learner: learnerDict } }}
    >
      <MyContent />
    </I18nProvider>
  );
}

function MyContent() {
  const { t, locale, direction } = useTranslation();
  return <h1>{t('runtime.loading')}</h1>;
}
```

## Responsibilities

### Locale Management

- `SUPPORTED_LOCALES` — `'en' | 'hi' | 'or'` (English, Hindi, Odia)
- `DEFAULT_LOCALE` — `'en'`
- `isValidLocale(value)` — type guard for supported locale codes
- Locale persisted to `localStorage` under key `open-edu-locale`

### Text Direction

- `getDirection(locale)` — returns `'ltr'` or `'rtl'` based on locale
- `I18nProvider` sets `document.documentElement.dir` automatically
- RTL locales: `ur`, `ar`, `fa`, `he`

### Translation Engine

`TranslationEngine` is the core class that manages dictionaries and resolves keys:

- **Key format:** `namespace.key` (e.g., `runtime.quiz.submit`, `learner.settings.theme`)
- **Fallback:** If a key is missing in the requested locale, the engine falls back to the default locale (`en`)
- **Interpolation:** `{{param}}` mustache-style placeholders (e.g., `Loaded {{type}}: {{title}}`)
- **Missing key callback:** `onMissing(key, locale)` for telemetry/debugging

### Namespace System

Four namespaces organize translations by consumer:

| Namespace | Consumer          | Example keys                       |
| --------- | ----------------- | ---------------------------------- |
| `runtime` | Runtime renderers | `quiz.submit`, `widget.load_error` |
| `learner` | Learner app       | `settings.theme`, `nav.home`       |
| `widgets` | Widget components | Widget-specific strings            |
| `schemas` | Schema validation | Validation messages                |

### React Integration

#### I18nProvider

Wraps the component tree and provides translation context:

```tsx
<I18nProvider
  locale="en" // Current locale
  supportedLocales={['en', 'hi']} // Available locales
  fallbackLocale="en" // Fallback for missing keys
  dictionaries={{ en: { runtime: dict } }} // Loaded dictionaries
  onMissing={(key, locale) => log(key)} // Optional missing key handler
>
  {children}
</I18nProvider>
```

The provider:

- Loads dictionaries into the translation engine
- Persists locale selection to `localStorage`
- Sets `document.documentElement.lang` and `.dir` on locale changes

#### useTranslation Hook

```tsx
const { locale, setLocale, direction, t, engine } = useTranslation();
```

Returns:

- `locale` — current locale code
- `setLocale(locale)` — switch locale at runtime
- `direction` — `'ltr'` or `'rtl'`
- `t(key, params?)` — translate a key with optional interpolation params
- `engine` — the underlying `TranslationEngine` instance

When used outside an `I18nProvider`, `useTranslation` returns identity defaults (locale `'en'`, `t` returns the raw key). This allows components to render without requiring the provider, but without translations.

#### LanguageSwitcher

A pre-built radio-group component for locale selection:

```tsx
import { LanguageSwitcher } from '@open-edu/i18n';

<LanguageSwitcher />;
```

Renders a `role="radiogroup"` with `aria-checked` radio buttons for each supported locale. Includes `aria-label="Select language"` for accessibility.

### Formatting Utilities

Locale-aware formatting wrappers around `Intl` APIs:

```ts
import { formatDate, formatNumber, formatPercent, formatCurrency } from '@open-edu/i18n';

formatDate(new Date(), 'en'); // Intl.DateTimeFormat
formatNumber(1234.5, 'hi'); // Intl.NumberFormat
formatPercent(0.85, 'en'); // 85%
formatCurrency(1500, 'en', 'INR'); // ₹1,500.00
```

### CLI Commands

Three CLI commands support translation workflow:

```bash
# Extract translatable strings from a package
edu i18n:extract ./my-lesson ./locales

# Validate translation completeness against English reference
edu i18n:validate ./my-lesson ./locales

# Find missing translations for a target language
edu i18n:missing ./locales ./target-lang
```

## Locale Files

Translations live in `packages/i18n/locales/{lang}/{namespace}.json`:

```
packages/i18n/locales/
├── en/
│   ├── runtime.json    # 16 keys — quiz, widget, reflection strings
│   ├── learner.json    # 39 keys — nav, settings, catalog strings
│   ├── widgets.json    # 8 keys — widget-specific strings
│   └── schemas.json    # 4 keys — validation messages
├── hi/                 # Hindi (planned)
└── or/                 # Odia (planned)
```

Key structure uses dot notation in JSON files (e.g., `"quiz.submit": "Submit"`) with the namespace prefix resolved by the engine at runtime.

## Integration Points

- **`@open-edu/runtime`** — `QuizRenderer`, `ReflectionRenderer`, and `WidgetRenderer` use `useTranslation()` for all UI strings
- **`@open-edu/learner`** — `AppShell`, `SettingsPage`, `CatalogPage` wrap in `I18nProvider` and use translated strings
- **`@open-edu/accessibility`** — Sets `document.documentElement.lang` and `dir` through `I18nProvider`
- **`@open-edu/widgets`** — `WidgetRenderProps` includes `locale` field; error boundaries use translated messages
- **`@open-edu/schemas`** — `localizedField()` helper available for future field-level localization
